# Contributing

Thanks for helping improve Battleship: Fleet Command. The project is
deliberately dependency-free: no package manager install, no build step, no
framework. Contributions are expected to keep it that way.

## Ground rules

- **No runtime dependencies.** The game must keep running from `index.html`
  over a plain static server. Do not add a bundler, transpiler, or npm
  dependency; there is no lockfile to update.
- **Vanilla ES modules only.** Browser code lives in `js/` as ES modules and is
  loaded directly by the browser.
- **Engine and presentation stay separate.** Rules live in `js/board.js`,
  `js/game.js`, `js/powers.js`, and `js/profile.js` and must remain testable
  under Node without a DOM. DOM wiring belongs in `js/main.js`.
- Match the surrounding style rather than introducing a new one.

## Local setup

```bash
git clone https://github.com/aackad21/battleship2.git
cd battleship2
npm start          # serves http://localhost:8000/index.html
```

`npm start` is a thin wrapper around `python3 -m http.server`; any static
server works. Opening `index.html` from the filesystem does not, because ES
modules require an HTTP origin.

## Before opening a pull request

```bash
npm test           # engine, powers, and profile suites
```

All three suites must pass. If you change rules, add a case to the suite that
covers the rule rather than adjusting an existing assertion to fit the new
behaviour.

For anything the player can see or interact with, also exercise it in a
browser. Follow the relevant scenario in
[`docs/acceptance-test-plan.md`](docs/acceptance-test-plan.md) and record the
result in your pull request. Automated suites do not cover layering, pointer
drag, audio, or layout.

## Pull requests

- One focused change per pull request.
- Fill in the pull request template, including how you verified the change.
- Note the browsers and viewports you tested when the change is visual.
- If you fix a defect, add it to the register in [`TESTING.md`](TESTING.md)
  using the existing entry format, and add a regression test.
- User-visible changes belong in the `Unreleased` section of
  [`CHANGELOG.md`](CHANGELOG.md).

## Reporting problems

Use the issue templates. Gameplay defects need the game mode, the rule
variant, the AI commander, exact reproduction steps, and any browser console
output. Security reports follow [`SECURITY.md`](SECURITY.md) instead of the
issue tracker.

## Assets

Ship art is generated by `tools/generate_ships.py`; regenerate rather than
hand-editing the SVGs. Any new sound or image must be CC0 or otherwise
redistributable, and must be credited in [`CREDITS.md`](CREDITS.md) with its
source and licence.
